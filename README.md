# Без очереди — MVP-прототип

Учебный фронтенд-прототип сервиса предзаказа готовой еды для сайта Финансового университета. Основан на концепции из презентации команды «5 и точка».

## Возможности демо

- меню блюд с категориями, ценами и условными остатками;
- корзина и изменение количества блюд;
- оформление заказа на сегодня;
- выбор «онлайн» или «при получении» (без реального списания денег);
- демонстрационный номер заказа и декоративный QR-макет;
- раздел «Мои заказы»;
- панель столовой: просмотр заказов, смена статуса, отметка оплаты при получении и корректировка остатков;
- сохранение демо-данных в `localStorage` браузера;
- адаптивный интерфейс для мобильных и настольных экранов.

## Запуск локально

1. Скачайте или распакуйте репозиторий.
2. Откройте `index.html` в браузере.

Для демонстрации достаточно современного браузера. Сборка и установка зависимостей не требуются. При желании можно запустить локальный сервер:

```bash
python -m http.server 8000
```

Затем откройте `http://localhost:8000`.

## Как опубликовать на GitHub

1. Создайте новый пустой репозиторий на https://github.com/new, например `bez-ocheredi-mvp`.
2. Распакуйте архив и откройте терминал в папке проекта.
3. Выполните команды:

```bash
git init
git add .
git commit -m "Initial MVP prototype"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/bez-ocheredi-mvp.git
git push -u origin main
```

Замените `ВАШ_ЛОГИН` на свой логин GitHub. После публикации ссылка будет иметь вид `https://github.com/ВАШ_ЛОГИН/bez-ocheredi-mvp`.

Чтобы показать работающий сайт по ссылке, включите GitHub Pages: **Settings → Pages → Deploy from a branch → main → /(root) → Save**. После публикации GitHub покажет адрес сайта в разделе Pages.

## Важно: ограничения MVP

Это демонстрация пользовательского сценария, а не production-система.

- данные хранятся только в браузере пользователя; разные устройства не синхронизируются;
- панель столовой открыта без авторизации;
- онлайн-оплата не подключена, платёжные данные не собираются;
- QR-код — декоративный макет, он не кодирует заказ и не предназначен для сканирования;
- нет серверной базы данных, реального кассового ПО, фискализации, email/SMS-уведомлений и полноценного офлайн-режима;
- данные можно сбросить, очистив хранилище сайта в браузере.

Перед реальным пилотом потребуется сервер/API, база данных, аутентификация и разграничение ролей, транзакционное резервирование остатков, интеграции оплаты и кассы, политика отмен/возвратов и тестирование безопасности.
